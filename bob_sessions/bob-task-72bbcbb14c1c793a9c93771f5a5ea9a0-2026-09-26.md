## 🔴 Breakage Report — 3/3 Probes Failed

---

### 1. CART-001 · **Cart total ignores quantity** · `HIGH`
**File:** [`src/app/api/cart/total/route.ts`](src/app/api/cart/total/route.ts)

Two bugs in the same route:
- **Bug A — wrong body shape:** The route unwraps `body.items`, but the probe POSTs a raw array. `body.items` is `undefined`, so the reduce starts on `[]` and returns `0` instead of `35`.
- **Bug B — quantity ignored in reduce:** Even with a correctly-wrapped payload, the `reduce` only sums `item.price` and never multiplies by `item.qty`. `10+15 = 25` instead of `10×2 + 15×1 = 35`.

**Repro:** `POST /api/cart/total` with `[{price:10,qty:2},{price:15,qty:1}]` → actual `0`, expected `35`

---

### 2. AUTH-001 · **Partial password accepted** · 🔴 `CRITICAL`
**File:** [`src/app/api/auth/login/route.ts`](src/app/api/auth/login/route.ts)

The password check uses `ACCOUNT.password.startsWith(password)` instead of strict equality. The real password is `shipit-now`; the probe submits `ship` (a valid 4-char prefix), which passes the check and returns `ok: true`.

Any prefix of the real password authenticates — an obvious security hole.

**Repro:** `POST /api/auth/login` with `{email:"buyer@demo.test", password:"ship"}` → accepted (should be rejected)

---

### 3. SEARCH-001 · **Category filter silently discarded** · 🟡 `MEDIUM`
**File:** [`src/app/api/search/route.ts`](src/app/api/search/route.ts)

The route reads the `category` query param, then immediately throws it away with `void category`. The `.filter()` call only runs the text-search predicate and never checks `item.category`. Requesting `?category=kitchen` returns all 4 catalog items (Trail Flask, Camp Mug, Ridge Jacket, Spice Kit) instead of the 2 kitchen items.

**Repro:** `GET /api/search?q=&category=kitchen` → 4 items returned, expected 2
