About the technology

Back for another hack: meet IBM Bob 2.0

After the IBM Bob hackathon in May, this challenge is built around Bob 2.0, an upgraded development partner for real systems, not only code snippets.

Bob 2.0 works with full repository context. It is meant to help a developer see how software is structured, reason through logic, and move through a large codebase.

It supports ordinary development tasks and is aimed at builders at any skill level. This second hackathon is the chance to put that version to work on a real project.

Second IBM Bob hackathon, now on Bob 2.0.

The challenge

Build with purpose using IBM Bob 2.0

Create a solution that improves a specific developer workflow, such as onboarding, debugging, code review, testing, application maintenance, or release and deployment.

Start by defining a problem where time, effort, or errors are too high today. Then, using IBM Bob 2.0, build a working prototype on a real or sample project that shows a full solution for that workflow.

Use features such as Agent mode, parallel tasks, subagents, and document understanding to handle several steps, not only to assist with coding. Show impact: less manual effort, fewer errors and less rework, or a shorter time to finish the task.

Get started

The event page lists these steps. Do them in order, and leave time for the submission assets.

  1. Join or form a team.

    Use the live dashboard or the lablab.ai Discord. Solo is allowed.

  2. Set up the IBM Bob 2.0 account.

    Check the inbox used at registration for the invite, then follow the hackathon guide. An IBMid is required. Install Bob IDE from bob.ibm.com. The guide says IDE v1.0.3 and v2.0.0 stop working on 30 September 2026, so use v2.0.2 or later.

  3. Read the challenge statement.

    The brief is wide on purpose. Read the challenge before choosing what to build.

  4. Choose a problem.

    Write a problem where time, effort, or errors are too high. The guide's examples, which are not a required list: onboarding assistant, code review coach, testing hub, release readiness assistant, legacy modernization accelerator.

  5. Review the deliverables.

    Read what to submit before the build, so the video, statements, and screenshots are not left for the last hour.

  6. Build the prototype.

    Use IBM Bob 2.0 on a new project that demonstrates the solution. Bob IDE has to be a core part of the work or the entry is not eligible.

  7. Ask in Discord.

    Mentors are in the lablab.ai Discord during the event.

  8. Submit before the deadline.

    Submissions close 27 September 2026 at 11:00 AM Eastern Daylight Time. Submit on the lablab.ai platform.

Technology and access

IBM Bob 2.0

Bob works directly with the codebase. Participants receive access at the start of the hackathon, for the duration of the event. Usage is limited. The project is expected to use Bob, not only mention it.

The guide assigns 40 Bobcoins to the hackathon account. At 100% usage, no more Bobcoins are added. Work can continue without them. In this install, click the gear in Bob IDE. That menu already lists the accounts. Choose ibm-coding-challenge-uat. If that account errors or shows no coins, choose ibm-coding-challenge-prod. Leave Personal alone so the free-trial balance is not spent. The invite email may name a team like ibm-hackathon-xxxx. That name is the account, not a hackathon teammate list.

Optional: IBM watsonx Orchestrate and watsonx.ai. Any other framework is allowed if Bob IDE stays central.

Official GitHub template. This folder keeps .gitignore and .bobignore so secrets stay out of the repo.

What to submit

Submit on the lablab.ai platform before the deadline. General rules: submission guidelines.

Basic information

  • Project title
  • Short description
  • Long description
  • IBM Bob usage statement
  • Technology and category tags

Application and code

  • Public code repository
  • IBM Bob task session summary screenshots
  • Demo application platform
  • Application URL

Media and presentation

  • Cover image
  • Video demonstration
  • Slide presentation

Requirements that disqualify a thin entry

  • Problem and solution statement, and the IBM Bob usage statement, are each 500 words or less.
  • The repository includes the files Bob assisted on, plus each team member's task session summary screenshots. Put exports in bob_sessions/.
  • The repository is public.
  • The video is 3 minutes or less, with at least 90 seconds of the solution on screen.
  • If IBM Cloud credentials show up in the repo, the guide says the cloud account can be suspended. Keep secrets in .env, which this .gitignore excludes.
Video demonstration

Upload an MP4 through the submission form. Judges will not watch past 3 minutes. Introduce the issue briefly, then spend at least 90 seconds showing the solution working, with narration. Show how Bob was used.

Long description: problem and solution, 500 words or less

State the problem, who the solution is for, how they use it, and why the approach is specific. Explain how it addresses the issue.

IBM Bob usage statement, 500 words or less

Say how and where the team used IBM Bob. If watsonx.ai or watsonx Orchestrate is part of the build, say how.

Code repository and session screenshots

Put the project in a public GitHub, GitLab, or Bitbucket repo. Include each member's Bob task session summary screenshots. The official template's ignore files are already in this folder.

Judging criteria

Application of technology
How complete and considered the project is, with a clear use of IBM Bob 2.0.
Presentation
How clear and effective the presentation is.
Business value
Practical impact on a high priority issue.
Originality
How specific the solution is, and how Bob 2.0 is applied to the stated issue.
